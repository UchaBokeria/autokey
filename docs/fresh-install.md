# Fresh install (new machine)

> Run top to bottom. Skips nothing required; marks everything optional.

## 0. Prereqs

- Go 1.27+ (`go version`)
- Node 16.17+ only if rebuilding the dashboard SPA (`make web`)
- Ubuntu / Arch / WSL2. No system Chrome needed (playwright drives
  its bundled Chromium unless you point it at one).

## 1. Install the binary

```sh
go install github.com/uchabokeria/autokey@latest
# or from source:
git clone https://github.com/uchabokeria/autokey.git && cd autokey
make build-static && sudo make install   # -> /usr/local/bin/autokey
```

## 2. First-run setup (interactive)

```sh
autokey setup
```

This creates `~/.autoApiKeys/` (`config.yaml`, `secrets.env` 0600,
`autokey.db`), asks for domain / providers / Cloudflare + KripiCard
keys / bind address, installs shell completions, and — by default —
enables the systemd user service (hook + tunnel ingress).

Answer `no` at the service prompt on machines that must stay manual;
bring it back later with `autokey service install`, remove with
`autokey service uninstall`.

## 3. Browser automation runtime (one-time)

```sh
autokey browser install   # playwright driver download (~170MB browsers)
```

The binary stays single — this is a runtime asset, not a dependency.

## 4. Point at your service

```sh
autokey services domain omegameta https://<dev-host-now>
# later, when devops publishes production:
autokey services domain omegameta https://<prod-url>
# show current:
autokey services domain omegameta
autokey services domain   # list all
```

Reminder: the domain is config, never code. Re-point + test manually
on every environment move.

## 5. Secrets checklist (`~/.autoApiKeys/secrets.env`, 0600)

| key | needed for |
|---|---|
| `HOOK_BEARER` | hook + dashboard auth (auto-generated by setup) |
| `CUSTOM_CARD_KEY` | add/decrypt own cards (`cards add`) |
| `CF_API_TOKEN` + `CF_ACCOUNT_ID` | `worker deploy` (Cloudflare Email Routing) |
| `KRIPI_API_KEY` | kripi provider only |
| `GMAIL_APP_PASSWORD` + `GMAIL_ADDRESS` | `inbox watch` fallback poller only |

## 6. Verify

```sh
autokey provider list
autokey cards list --provider custom
autokey inbox otp --email nobody@example.com --latest   # expect "no code found"
autokey service status
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8765/v1/inbox \
  -H "Authorization: Bearer $HOOK_BEARER" -d '{}'   # 400 = alive, 401 = bad bearer
```

## 7. Optional extras

- Dashboard: `autokey dashboard` (:8766 = hook.port+1), same bearer.
- Residential egress for browser traffic only:
  `autokey setup` asks, or set `browser.proxy_url` / `--proxy` per run.
  API/mail stay direct.
- CAPTCHA policy (never solved): default `pause-manual`;
  `--captcha-strategy abort-quarantine|backoff-retry`.
- 24/7 host: see `docs/blackwall.md` for the blackwall runbook.
